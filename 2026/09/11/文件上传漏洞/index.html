文件上传漏洞

文件上传漏洞

一、定义

由于程序员在对用户文件上传部分的控制不足或者处理缺陷，导致用户可以越过其本身权限向服务器上传可执行的恶意动态脚本文件。

这里上传的文件可以是：木马，病毒，恶意脚本或者 WebShell 等。

二、产生原因

  • 对于上传文件的后缀名（扩展名）没有做较为严格的限制
  • 对于上传文件的 MIMETYPE（用于描述文件的类型的一种表述方法）没有做检查
  • 权限上没有对于上传的文件目录设置不可执行权限，（尤其是对于 shebang 类型的文件）
  • 对于 Web Server 等上传文件或者指定目录的行为没有做限制

三、原理

先将表单设为 multipart/form-data，同时加入文件域。

再通过 HTTP 协议将文件内容发送到服务器，此时服务器端读取该分段（multipart）的数据信息，并将其中的文件内容提取出来保存。

通常，在进行文件保存的时候，服务器端会读取文件的原始文件名，并从这个原始文件名中得出文件的扩展名，而后随机为文件起一个文件名（为了防止重复），并且加上原始文件的扩展名来保存到服务器上。

1. 前端限制（JS 检测）

原理

在表单中使用 onsubmit=checkFile() 调用 JS 函数来检查上传文件的扩展名。

当用户在客户端选择文件点击上传的时候，客户端还没有向服务器发送任何消息，就对本地文件进行检测来判断是否是可以上传的类型，这种方式称为前台脚本检测扩展名。

2. 检查扩展名

黑名单策略

文件扩展名在黑名单中的为不合法后缀，将被拒绝此次上传。

白名单策略

文件扩展名不在白名单中的均为不合法。

原理

当浏览器将文件提交到服务器端的时候，服务器端根据设定的黑白名单对浏览器提交上来的文件扩展名进行检测，如果上传的文件扩展名不符合黑白名单的限制，则不予上传，否则上传成功。

绕过方法

在一些 Web Server 中，存在解析漏洞：

服务器 漏洞 绕过方式
IIS 6.0 目录解析漏洞 网站目录中有一个 /.asp/ 目录，此目录下面的一切内容都会被当作 ASP 脚本来解析
IIS 6.0 分号漏洞 IIS 在解析文件名的时候可能将分号后面的内容丢弃，如 a.asp;jpg

Apache 1.x/2.x 解析漏洞 上传 a.php.rar、a.php.gif 类型的文件名，Apache 从右向左读，遇到不能识别的扩展名则跳过，直接将类型识别为 PHP

3. MIME 类型检测

服务器会检查 HTTP 请求头中的 Content-Type 字段。

绕过方式：抓包修改 Content-Type 为允许的类型，如 image/jpeg、image/png、image/gif。

4. 文件头检测

服务器会检查文件开头的内容（魔术字节）。

绕过方式：在木马文件开头加上合法的文件头：

文件类型 文件头

PNG 89 50 4E 47

5. 文件内容检测

服务器会对文件内容进行扫描，检查是否包含危险函数。

绕过方式：

  • 使用短标签 <?= 代替 <?php
  • 使用大小写混淆、字符串拼接
  • 使用无字符 webshell
  • 使用图片马（图片中嵌入 PHP 代码）

6. 二次渲染绕过

服务器会对上传的图片进行重新渲染（如 imagecreatefromjpeg + imagejpeg），这会破坏原始数据。

绕过方式：

  • 对比渲染前后的图片，找到未被修改的像素区域，将恶意代码注入到该区域
  • GIF 图片的二次渲染通常只保留第一帧，可以把代码放在第一帧之外

六、文件上传防御

  1. 白名单验证：只允许特定扩展名，如 jpg、png、gif
  2. MIME 类型校验：校验 Content-Type，同时结合文件头校验
  3. 文件内容检测：扫描危险函数、恶意代码
  4. 重命名文件：随机生成文件名，不保留原始扩展名
  5. 限制文件大小：防止大文件上传导致拒绝服务
  6. 上传目录不可执行：关闭上传目录的脚本执行权限
  7. 分离存储：将上传文件存储在独立的服务器或对象存储中
  8. 图片二次渲染：对上传的图片进行重新渲染，去除潜在恶意代码
  9. WAF：部署 Web 应用防火墙拦截常见上传攻击
  10. 定期扫描：定期检查上传目录，发现异常文件

七、总结

维度 要点
本质 服务器对上传文件校验不足，导致恶意脚本被上传并执行
常见检测 前端 JS、扩展名、MIME、文件头、文件内容、二次渲染
常见绕过 抓包改包、大小写、双写、特殊后缀、%00 截断、.htaccess、条件竞争
常见目标 上传 WebShell，获取服务器权限
防御核心 白名单 + 内容检测 + 重命名 + 不可执行目录
