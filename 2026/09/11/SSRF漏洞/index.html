SSRF漏洞

SSRF

一、定义

服务器端请求伪造（Server-Side Request Forgery），是一种由攻击者构造形成、由服务端发起请求的安全漏洞。

一般情况下，SSRF 攻击的目标是从外网无法访问的内部系统。因为它是由服务端发起的，所以它能够请求到与它相连、而与外网隔离的内部系统。

二、原理

由于服务端提供了从其他服务器应用获取数据的功能，且没有对目标地址做过滤与限制。

SSRF 是利用存在缺陷的 Web 应用作为代理，攻击远程和本地的服务器。

三、SSRF 的类型

1. 按回显方式分类

类型 说明
回显型 SSRF 服务端将请求结果直接返回给攻击者，可直接读取内网资源
盲 SSRF 服务端不返回请求结果，只能通过时间延迟、DNS 请求等侧信道判断
半盲 SSRF 不返回响应体，但返回状态码或响应头等信息

2. 按攻击目标分类

类型 说明
内网探测 探测内网主机存活、开放端口、服务版本
本地文件读取 通过 file:// 协议读取服务器本地文件
内网服务攻击 利用 gopher:// 攻击内网 Redis、MySQL、FastCGI 等
云元数据获取 读取云服务器元数据接口，获取临时凭证

五、常见利用协议

SSRF 漏洞常被用来探测内网、读取本地文件，常见利用协议包括：

协议 用途 示例
http / https 探测内网 Web 服务 http://192.168.1.1/admin
file 读取本地文件 file:///etc/passwd
dict 探测内网端口、服务 dict://127.0.0.1:6379/info
gopher 构造任意 TCP 数据包，攻击内网 Redis、MySQL、FastCGI 等 gopher://127.0.0.1:6379/_...
ftp 探测 FTP 服务 ftp://127.0.0.1:21
ldap 探测 LDAP 服务 ldap://127.0.0.1:389
tftp 探测 TFTP 服务 tftp://127.0.0.1:69

其中 gopher 协议功能最强，常被用来攻击内网未授权服务。

七、SSRF 绕过技巧

1. 限制为 http 协议时

  • 尝试 file、gopher、dict 等协议
  • 尝试 HTTP、HttP 等大小写变形
  • 尝试 http:// 省略为 //
  • 尝试 http:/、http:\\\\ 等变形

2. 限制为内网 IP 时

  • 使用 IP 的多种表示形式：
    • 十进制：http://2130706433/
    • 八进制：http://0177.0.0.1/
    • 十六进制：http://0x7f.0.0.1/
    • 混合：http://0x7f.1/
    • 省略：http://127.1/
  • 使用 DNS 解析到内网 IP 的域名
  • 使用 xip.io、nip.io 等 DNS 服务
  • 使用 URL 编码、双重编码
  • 使用 @ 符号：http://expected.com@127.0.0.1/
  • 使用 # 截断：http://127.0.0.1#expected.com
  • 使用 ? 截断：http://127.0.0.1?expected.com

3. 限制为白名单域名时

  • 使用 @ 绕过：http://whitelist.com@127.0.0.1/
  • 使用子域名：http://127.0.0.1.whitelist.com/
  • 使用 DNS Rebinding
  • 使用 302 跳转绕过

4. 限制为特定端口时

  • 使用 302 跳转到其他端口
  • 使用 gopher 协议指定端口
  • 使用 DNS Rebinding 解析到其他端口

八、注意事项

  • 一般情况下 PHP 不会开启 fopen 的 gopher wrapper。
  • file_get_contents 的 gopher 协议不能 URL 编码。
  • file_get_contents 关于 Gopher 的 302 跳转会出现 bug，导致利用失败。
  • curl/libcurl 7.43 上 gopher 协议存在 bug（%00 截断），经测试 7.49 可用。
  • curl_exec() 默认不跟踪跳转。
  • file_get_contents() 支持 php://input 协议。

九、SSRF 防御

通常有以下 5 个思路：

  1. 过滤返回信息：验证远程服务器对请求的响应是比较容易的方法。如果 Web 应用是去获取某一种类型的文件，那么在把返回结果展示给用户之前，先验证返回的信息是否符合标准。

  2. 统一错误信息：避免用户可以根据错误信息来判断远端服务器的端口状态。

  3. 限制请求的端口：仅允许 HTTP 常用端口，比如 80、443、8080、8090。

  4. 黑名单内网 IP：避免应用被用来获取内网数据，攻击内网。

  5. 禁用不需要的协议：仅仅允许 HTTP 和 HTTPS 请求。可以防止类似于 file:///、gopher://、ftp:// 等引起的问题。

补充：更严格的做法

  • 使用白名单限制目标地址
  • 校验 DNS 解析结果，防止 DNS Rebinding
  • 禁止跟随 302 跳转
  • 将远端资源存取功能切割成不同子网路以降低 SSRF 冲击
  • 在防火墙策略或网络访问控制规则中实施 “默认全拒绝”
  • 不要使用黑名单或正则表达式来缓解 SSRF

十、总结

维度 要点
本质 服务端代替攻击者发起请求
核心条件 服务端提供获取远程资源的功能，且未对目标地址做严格过滤
常见函数 file_get_contents、fsockopen、curl_exec
常用协议 http、file、dict、gopher、ftp
常见目标 内网服务、本地文件、云元数据、Redis、MySQL、FastCGI
绕过思路 IP 变形、协议变形、@ 符号、DNS Rebinding、302 跳转
防御核心 白名单 + 协议限制 + 端口限制 + DNS 校验
