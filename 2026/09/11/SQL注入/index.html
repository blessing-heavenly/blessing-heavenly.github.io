SQL注入总结

SQL注入知识总结

一、定义

其本质就在于攻击者向 Web 应用提交了包含恶意 SQL 代码的数据输入，使得原本预期执行的 SQL 查询被篡改。这是由于在数据交互中，前端的数据传入到后台处理时，后端没有做严格的判断，导致其传入的恶意 “ 数据 “ 拼接到 SQL 语句中后，被当作 SQL 语句的一部分执行。

SQL 注入，就是通过把 SQL 命令插入到 Web 表单递交或输入域名或页面请求的查询字符串，最终达到欺骗服务器执行恶意的 SQL 命令。

SQL 注入的本质就是打破原本传递数据的区域边界，插入逻辑代码。

二、行使条件

  1. 参数用户可控，即用户能控制输入的内容
  2. 参数带入数据库查询，即传入的参数能拼接到 SQL 语句中，且代入数据库中查询

联合查询 / Union 注入

利用 union 函数联合两个或者多个表同时进行查询。

union 的作用：

  • 合并结果集：当需要将多个查询结果合并成一个结果集时，可以使用 union 函数。这样可以简化查询操作，减少代码的复杂性。
  • 去重数据：union 函数会自动去重，即将重复的行从结果集中剔除，只返回唯一的行。这在需要对两个或多个表中的数据进行合并，并消除重复数据时非常有用。
  • 扩展查询：使用 union 函数可以将多个查询结果合并在一起，从而扩展查询的范围。使用者可以在每个 SELECT 语句中使用不同的条件和过滤器，从不同的表中获取数据，并将它们合并成一个结果集。

利用条件：

  • 页面有数据回显
  • 查询字段数前后必须一致
  • 使用其前条数据查询失败

宽字节注入

先使用过滤函数对传入数据进行过滤，当数据传入数据库进行代码执行时，前后编码不一致，这时数据库采用了宽字节编码，由于编码的识别差异性特点，攻击者可以通过恶意构造使原本的闭合逃逸，从而可以被利用。

注意：

  • 窄字节：一个字符的大小为一个字节
  • 宽字节：一个字符的大小为两个字节
  • 所有英文默认占一个字节，汉字占两个字节。

二次注入

在第一次进行数据库插入数据的时候，仅仅只使用了 addslashes 函数或者是借助 get_magic_quotes_gpc 函数对其中的特殊字符进行了转义。

注意：addslashes 使用时的参数在过滤后会添加 \ 进行转义，但是 \ 并不会插入到数据库中，在写入数据库的时候还是保留了原来的数据。

在将数据存入到数据库中之后，开发者就认为数据是可信的。在下一次进行查询的时候，直接从数据库中取出了脏数据，没有进行进一步的检验和处理，这样就会造成 SQL 的二次注入。

堆叠注入

执行代码中使用了可执行针对一个或多个数据库的查询函数。因为 MySQL 数据库的 SQL 语句在结束的时候是以 ; 结尾，在执行多条语句时就要使用结束隔离符隔开。

堆叠注入就是通过结束符来执行多条 SQL 语句。

利用条件：

  1. 目标存在 SQL 注入漏洞
  2. 对 ; 未过滤
  3. 目标中间层查询数据库信息时可以同时执行多条 SQL 语句。
    • 比如 PHP 中 mysqli_multi_query() 函数，这个函数在支持同时执行多条 SQL 语句，而与之对应的 mysqli_query() 函数一次只能执行一条 SQL 语句。

利用方式：

  • 执行多条查询 SQL 语句时，语句之间以分号（;）隔开，在语句中构造需要执行攻击的语句。

七、防御建议

  1. 使用参数化查询（预编译语句）：最有效的防御方式，将 SQL 语句与数据分离。
  2. 对输入进行严格校验：白名单验证，过滤特殊字符。
  3. 最小权限原则：数据库账号只授予必要的权限，避免使用 root。
  4. 关闭错误回显：避免将数据库错误信息直接返回给用户。
  5. 使用 WAF：Web 应用防火墙可以拦截常见的 SQL 注入攻击。
  6. 定期更新和打补丁：保持数据库和 Web 应用最新版本。
