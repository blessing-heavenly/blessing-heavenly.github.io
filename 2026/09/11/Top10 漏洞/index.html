OWASP Top 10 漏洞总结（2021版）

本文基于 OWASP Top 10 2021 版本整理。2021版相比2017版产生了三个新类别，四个类别的命名和范围发生了变化，并进行了部分整合。

版本变化说明

A02-失效的身份认证 A07-身份识别和身份验证错误（排名下滑）

一、A01:2021 - 失效的访问控制（Broken Access Control）

1. 攻击方式

用户能够访问其权限之外的资源或功能，如水平越权查看他人订单、垂直越权普通用户访问管理后台。

2. 漏洞原因

  • 未对用户身份和权限进行严格校验
  • 直接通过参数传递资源标识，未做归属验证
  • 默认允许而非默认拒绝的访问策略
  • JWT 等令牌中允许使用 none 算法

3. 漏洞防护

  • 默认拒绝所有访问，除非明确允许
  • 实施最小权限原则
  • 记录访问控制失败的日志
  • 禁用 JWT 等令牌中的 none 算法
  • CORS 配置严格化
  • 对参数进行白名单过滤
  • 限制下载文件的类型

二、A02:2021 - 加密机制失效（Cryptographic Failures）

1. 攻击方式

攻击者利用加密缺失或弱加密算法，获取敏感数据（密码、信用卡、个人信息等）。

2. 漏洞原因

  • HTTP 明文传输（未强制 HTTPS）
  • 密码使用 MD5/SHA1 等弱哈希存储（应使用 bcrypt/Argon2）
  • 数据库敏感字段未加密
  • SSL/TLS 证书过期或使用自签名证书
  • 使用过时的加密协议（如 FTP、telnet）

3. 漏洞防护

  • 强制 HTTPS（HSTS + 301 重定向）
  • 使用 TLS 1.2+（禁用 SSLv3/TLS 1.0）
  • 密码使用 bcrypt 加盐哈希存储
  • 敏感字段使用 AES-256 加密存储
  • 确保所有敏感数据在静态时加密
  • 使用最新且标准的强算法、协议和密钥
  • 对包含敏感数据的响应禁用缓存
  • 不使用 FTP 等遗留协议

三、A03:2021 - 注入（Injection）

注：2021版中，跨站脚本（XSS） 已被纳入此类别。详细内容见 XSS 漏洞。

1. 攻击方式

利用应用程序弱点，通过恶意字符将恶意代码写入数据库，获取敏感数据或进一步在服务器执行命令。

2. 漏洞原因

  • 未审计的数据输入框
  • 使用网址直接传递变量
  • 未过滤的特殊字符
  • SQL 错误回显

  • SQL 操作使用 PreparedStatement（参数化查询）
  • SQL 服务运行于专门的账号，并且使用最小权限
  • 限制 SQL 服务的远程访问
  • 代码审计
  • 使用成熟的 WAF

四、A04:2021 - 不安全设计（Insecure Design）

2021年新增类别，一出场就高居第四位。

1. 攻击方式

攻击者利用应用程序设计与架构中的缺陷进行攻击。这类缺陷无法通过完美的编码来修复，因为所需的安全控制从未被设计出来以抵御特定攻击。

2. 漏洞原因

  • 缺少威胁建模
  • 未使用安全设计模式
  • 缺乏参考架构
  • 未建立安全开发生命周期（SDLC）

3. 漏洞防护

  • 建立与使用安全开发生命周期，协同应用安全专业人士评估与设计安全与隐私相关的控制措施
  • 建立与使用安全设计模式的函数库或已完成可使用的组件
  • 使用威胁建模在关键的认证、访问控制、业务逻辑和关键流程上
  • 编写单元测试和集成测试来验证所有关键流程是否抵抗威胁模型
  • 将限速和资源限制作为设计的一部分

五、A05:2021 - 安全配置错误（Security Misconfiguration）

1. 攻击方式

攻击者利用错误配置攻击，获取敏感数据或者提升权限。

2. 漏洞原因

开发或者维护人员设置了错误的配置。如 Python 开发中对于 Django 框架在生产环境启用了 Debug 模式。

注：2021版中，XML外部实体（XXE） 已被合并至此类别。

3. 漏洞防护

  • 检查文件扩展名
  • 重命名上传文件
  • 控制上传文件的权限，如关闭执行权限
  • 移除不使用的页面，如安装目录文件
  • 移除临时文件、备份文件
  • 不使用简单的命名规则，防止猜测
  • 定义白名单
  • 关闭 Debug 模式
  • 修改默认账户密码
  • 最小化安装组件
  • 禁用 Web 服务器目录列表

六、A06:2021 - 自带缺陷和过时的组件（Vulnerable and Outdated Components）

1. 攻击方式

攻击者利用应用程序技术栈中的框架、库、工具等的已知漏洞进行攻击，获取高权限或者敏感数据。

2. 漏洞原因

应用程序技术栈中使用的框架、库、工具爆出了漏洞，应用程序未能及时更新与修复。

3. 漏洞防护

  • 及时更新、修复组件漏洞
  • 移除不再使用的依赖组件
  • 使用依赖扫描工具（如 OWASP Dependency-Check）
  • 维护软件物料清单（SBOM）
  • 持续监控 CVE 和 NVD 等漏洞数据库
  • 仅从受信任的官方源获取组件

七、A07:2021 - 身份识别和身份验证错误（Identification and Authentication Failures）

1. 攻击方式

攻击者利用网站应用程序中的身份认证缺陷获取高权限并进行攻击应用服务。

2. 漏洞原因

应用程序身份认证系统认证缺陷。

3. 弱密码攻击

身份认证非常容易受到弱密码攻击，常用的弱密码攻击方式：

  • 常用密码攻击：使用泄露的密码字典攻击
  • 使用公司名称缩写、域名、电话号码
  • 全数字、英文的简单密码
  • 账号与密码相同的
  • 不同网站、电脑、APP 使用相同的密码
  • 撞库攻击（Credential Stuffing）

4. 漏洞防护

  • 网站的登录页面使用加密连接
  • 网站具有良好的权限控制与管理
  • 网站具备超时注销机制
  • 启用多因素认证（MFA）
  • 密码加盐哈希存储
  • 限制登录失败次数
  • 检查新密码或修改后的密码是否在 Top 10,000 弱密码列表中
  • 不在 URL 中暴露会话 ID

八、A08:2021 - 软件和数据完整性故障（Software and Data Integrity Failures）

2021年新增类别，原“不安全反序列化”被归入此类别。

1. 攻击方式

攻击者利用软件更新、关键数据及 CI/CD 流程中未经完整性验证的假设进行攻击。

2. 漏洞原因

  • 未对软件或数据的来源进行验证
  • 从未经验证的仓库获取依赖
  • 反序列化不可信数据
  • CI/CD 流水线缺乏完整性校验

3. 漏洞防护

  • 使用数字签名或类似机制验证软件或数据来自预期来源且未被篡改
  • 确保库和依赖从受信任的仓库获取
  • 使用软件供应链安全工具（如 OWASP Dependency-Check 或 OWASP CycloneDX）验证组件不含已知漏洞
  • 对序列化数据进行完整性检查
  • 隔离反序列化操作环境

九、A09:2021 - 安全日志和监控故障（Security Logging and Monitoring Failures）

1. 漏洞原因

对于日志记录的监控不足，造成攻击者攻击系统、应用、盗取数据等操作无法被发现和追查。

2. 漏洞防护

  • 启用日志监控、告警机制
  • 启用异地监控，C/S 架构的监制机制
  • 尽可能完整地记录所有日志
  • 集中式日志管理
  • 定期审计日志
  • 对异常行为进行告警

十、A10:2021 - 服务端请求伪造（Server-Side Request Forgery, SSRF）

2021年新增类别。

1. 攻击方式

攻击者通过构造恶意请求，让服务器端向攻击者指定的目标发起请求，从而访问内部系统或敏感资源。

2. 漏洞原因

  • 应用程序未验证用户提供的 URL 或目标地址
  • 允许服务器访问内部网络资源
  • 未对请求的目标进行限制

3. 漏洞防护

从网络层着手：

  • 将远端资源存取功能切割成不同子网路以降低 SSRF 冲击
  • 在防火墙策略或网络访问控制规则中实施**“默认全拒绝”**

从应用层着手：

  • 过滤并验证来自用户端的全部输入
  • 使用正向白名单强制 URL schema、端口和目标地址
  • 不要将原始响应发送给客户端
  • 禁用 HTTP 重定向
  • 注意 URL 一致性以避免 DNS rebinding 等攻击

不要使用黑名单或正则表达式来缓解 SSRF。

总结

编号 风险 核心防护思路
A01 失效的访问控制 默认拒绝、最小权限、每次校验
A02 加密机制失效 强制 HTTPS、强哈希、AES-256 加密
A03 注入 参数化查询、输入校验、最小权限
A04 不安全设计 威胁建模、安全设计模式、SDLC
A05 安全配置错误 关闭 Debug、最小化安装、白名单
A06 自带缺陷和过时的组件 依赖扫描、及时更新、SBOM
A07 身份识别和身份验证错误 MFA、强密码策略、会话管理
A08 软件和数据完整性故障 数字签名、信任源、供应链安全工具
A09 安全日志和监控故障 集中日志、告警、审计
A10 服务端请求伪造 网络隔离、输入验证、正向白名单
